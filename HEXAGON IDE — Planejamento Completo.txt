HEXAGON IDE — Planejamento Completo
TAREFA 1 — Entendimento do Problema
Objetivo principal
O HEXAGON IDE resolve um problema específico: quem usa o Claude Code em múltiplas VPS diferentes precisa trocar de conta manualmente o tempo todo, e isso gera conflito de autenticação. O app automatiza e organiza tudo isso em uma interface visual.

Público-alvo
Desenvolvedores que trabalham com:

Múltiplos servidores VPS simultaneamente
Múltiplas contas Claude Code (pessoal, trabalho, clientes)
Projetos remotos que precisam de acesso SSH constante
Equipes que têm VPS separadas por ambiente (dev/staging/produção)
Problemas reais que resolve
Problema	Como o HEXAGON IDE resolve
Trocar de conta Claude manualmente	Cada VPS já tem sua conta associada
Lembrar qual servidor é qual	Painel visual com nome, IP e status
Abrir VS Code na VPS errada	Botão único que já abre no lugar certo
Editar arquivos remotos sem VS Code	IDE integrado com Monaco + SFTP
Terminal perdido sem contexto	Múltiplas abas com histórico
Git manual via SSH	Painel Source Control integrado
Não saber o que está rodando na VPS	Monitoramento de processos (roadmap)
Por que é diferente do VS Code Remote SSH
O VS Code Remote SSH é excelente, mas:

Não gerencia múltiplas contas Claude
Não tem visão de quais VPS estão acessíveis
Não tem o chat Claude integrado ao editor
Não tem port forwarding visual
Não faz deploy local → VPS com um clique
Não separa ambientes por conta IA
O HEXAGON IDE é o painel de controle que organiza tudo. O VS Code Remote SSH é apenas uma das ferramentas que ele pode abrir.

Riscos do produto
Risco	Impacto	Mitigação
Editar arquivo direto em produção	Alto	Badge PRODUÇÃO vermelho pulsante
Credenciais SSH expostas	Crítico	Criptografia AES-256; nunca texto puro
Conflito entre múltiplos túneis SSH	Médio	TunnelService com controle de sessões
LSP consumindo muita memória	Baixo	LSP opt-in; desligado por padrão
App quebrar ao perder conexão SSH	Médio	Reconexão automática + estado de erro visível

TAREFA 4 — Arquitetura do Sistema
Visão geral (nível iniciante)
Pense no HEXAGON IDE como um prédio de 3 andares:


┌─────────────────────────────────────────┐
│  3º Andar — RENDERER (o que você vê)   │
│  React + Monaco + xterm.js              │
│  A janela do app, botões, telas         │
├─────────────────────────────────────────┤
│  2º Andar — PRELOAD (o porteiro)        │
│  contextBridge — autoriza mensagens     │
│  Define o que o 1º pode pedir ao 3º    │
├─────────────────────────────────────────┤
│  1º Andar — MAIN PROCESS (a máquina)   │
│  Node.js — acesso total ao sistema      │
│  SSH, SFTP, banco, arquivos, processos  │
└─────────────────────────────────────────┘
        ↕ (só via mensagens autorizadas)
┌─────────────────────────────────────────┐
│  SUBSOLO — Serviços externos            │
│  VPS via SSH · SQLite · sistema de arquivos│
└─────────────────────────────────────────┘
Por que essa separação? Segurança. O renderer (React) não pode acessar o sistema diretamente. Tudo passa pelo "porteiro" (preload), que só deixa passar mensagens autorizadas.

Camada Frontend (Renderer)
Tecnologia: React 18 + Vite + TypeScript + Tailwind CSS

Responsabilidades:

Exibir todas as telas e componentes
Gerenciar estado local (quais abas estão abertas, qual arquivo está ativo)
Renderizar Monaco Editor, xterm.js, árvore de arquivos
Enviar ações para o main process via window.electron.invoke(canal, dados)
Receber eventos do main process via window.electron.on(canal, callback)
Estado principal:


openFiles[]      → arquivos abertos no editor
activeTab        → arquivo ativo no painel 1
activeTab2       → arquivo ativo no painel 2 (split)
termTabs[]       → abas de terminal
tunnels[]        → túneis SSH ativos
chatMessages[]   → histórico do chat Claude
gitStatus        → status do repositório
Camada Preload (Porteiro)
Tecnologia: contextBridge do Electron

Responsabilidades:

Definir a lista explícita de canais IPC autorizados
Expor window.electron.invoke, window.electron.send e window.electron.on
Bloquear qualquer canal não listado
Regra de ouro: Se um canal não está na lista do preload, o renderer nunca pode usá-lo.

Camada Main Process (A Máquina)
Tecnologia: Node.js + electron-vite + @cwm/core

Responsabilidades:

Receber e validar mensagens do renderer (Zod)
Gerenciar conexões SSH (ssh2)
Gerenciar sessões SFTP (ssh2)
Executar comandos na VPS
Criar e destruir túneis SSH
Ler/escrever banco SQLite (Prisma)
Ler/escrever arquivos locais (node:fs)
Abrir janelas externas (VS Code, Chrome DevTools)
Como cada parte se conecta
Monaco Editor → arquivo remoto:

Usuário clica no arquivo no explorer
Renderer envia sftp:readFile ao main
Main lê via SFTP e retorna o conteúdo
Renderer carrega no Monaco
Usuário edita → Ctrl+S → renderer envia sftp:writeFile
Main salva na VPS via SFTP
Terminal xterm.js → SSH:

Renderer solicita terminal:open
Main cria sessão SSH interativa (ssh2 shell mode)
Main emite eventos terminal:data ao renderer conforme dados chegam
Renderer exibe no xterm.js
Usuário digita → renderer envia terminal:input → main envia ao SSH
Git → VPS:

Renderer solicita git:status
Main executa git status --porcelain -b via SSH exec
Parseia a saída e retorna objeto estruturado
Renderer exibe no painel Source Control
Chat Claude:

Renderer constrói prompt (contexto do projeto + arquivo + pergunta)
Escreve o prompt em /tmp/hexagon_chat_xxx.txt via SFTP
Main executa claude -p "$(cat arquivo.txt)" via SSH exec
Retorna a resposta como string
Renderer parseia e exibe no painel de chat
Banco de dados
Tecnologia: SQLite + Prisma ORM + better-sqlite3

Onde fica: C:\Users\{usuario}\AppData\Roaming\HEXAGON IDE\cwm.db

Por que SQLite? É local, sem servidor, fácil de fazer backup, funciona offline.

TAREFA 6 — Modelagem de Dados
Entidades e Relacionamentos

VpsServer (1) ──── (N) RemoteProject
VpsServer (1) ──── (N) ClaudeAccount
RemoteProject (N) ──── (1) ClaudeAccount
AppSettings (1) ──── (único por instalação)
LaunchHistory (N) ──── (1) RemoteProject
Entidade: VpsServer
Objetivo: Armazenar os dados de acesso a uma VPS.

Campo	Tipo	Descrição
id	String (CUID)	Identificador único
name	String	Nome amigável (ex: "VPS-Produção")
host	String	IP ou hostname
port	Int	Porta SSH (padrão 22)
username	String	Usuário SSH (ex: root)
defaultPath	String	Caminho padrão ao abrir
sshPassword	String?	Senha ou passphrase — criptografada AES-256
createdAt	DateTime	Data de criação
Dados sensíveis: sshPassword — armazenada cifrada, nunca em texto puro.

O que NUNCA salvar: Token Claude, API Key Anthropic, conteúdo de chave SSH privada.

Entidade: RemoteProject
Objetivo: Representar um projeto em uma VPS específica.

Campo	Tipo	Descrição
id	String (CUID)	Identificador único
name	String	Nome do projeto
description	String	Descrição opcional
remotePath	String	Caminho na VPS (ex: /var/www/projeto)
gitRepo	String?	URL do repositório Git
vpsServerId	String	FK → VpsServer
claudeAccountId	String?	FK → ClaudeAccount
createdAt	DateTime	Data de criação
Entidade: ClaudeAccount
Objetivo: Registro lógico de conta Claude — sem credenciais.

Campo	Tipo	Descrição
id	String (CUID)	Identificador único
name	String	Nome amigável (ex: "Claude Conta A")
email	String?	E-mail opcional para referência
vpsServerId	String?	VPS onde esta conta está logada
notes	String?	Anotações do usuário
O que NUNCA salvar: Senha, token OAuth, cookie de sessão, API Key.

Entidade: AppSettings
Objetivo: Configurações locais do aplicativo.

Campo	Tipo	Descrição
id	String (sempre "default")	Singleton
vscodePath	String	Caminho do executável VS Code
vscodeInsidersPath	String	Caminho do VS Code Insiders
sshKeyPath	String?	Caminho da chave SSH padrão
theme	String	Tema da UI (dark/light)
updatedAt	DateTime	Última atualização
Entidade: LaunchHistory
Objetivo: Histórico de quando ambientes foram abertos.

Campo	Tipo	Descrição
id	String (CUID)	Identificador único
projectId	String	FK → RemoteProject
launchType	String	"vscode", "ide", "terminal"
success	Boolean	Se a abertura foi bem-sucedida
errorMessage	String?	Mensagem de erro, se houver
createdAt	DateTime	Quando foi aberto
Schema Prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
}

model VpsServer {
  id          String    @id @default(cuid())
  name        String
  host        String
  port        Int       @default(22)
  username    String
  defaultPath String    @default("/root")
  sshPassword String?   // criptografado AES-256
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt

  projects        RemoteProject[]
  claudeAccounts  ClaudeAccount[]
  launchHistories LaunchHistory[]

  @@map("vps_servers")
}

model RemoteProject {
  id             String    @id @default(cuid())
  name           String
  description    String    @default("")
  remotePath     String
  gitRepo        String    @default("")
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt

  vpsServerId      String
  vpsServer        VpsServer      @relation(fields: [vpsServerId], references: [id], onDelete: Cascade)
  claudeAccountId  String?
  claudeAccount    ClaudeAccount? @relation(fields: [claudeAccountId], references: [id])
  launchHistories  LaunchHistory[]

  @@map("projects")
}

model ClaudeAccount {
  id          String    @id @default(cuid())
  name        String
  email       String?
  notes       String    @default("")
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt

  vpsServerId String?
  vpsServer   VpsServer?      @relation(fields: [vpsServerId], references: [id])
  projects    RemoteProject[]

  @@map("claude_accounts")
}

model AppSettings {
  id                  String   @id @default("default")
  vscodePath          String   @default("code")
  vscodeInsidersPath  String   @default("code-insiders")
  sshKeyPath          String?
  updatedAt           DateTime @updatedAt

  @@map("settings")
}

model LaunchHistory {
  id           String   @id @default(cuid())
  launchType   String   // "vscode" | "ide" | "terminal"
  success      Boolean
  errorMessage String?
  createdAt    DateTime @default(now())

  projectId  String
  project    RemoteProject @relation(fields: [projectId], references: [id], onDelete: Cascade)
  vpsId      String
  vpsServer  VpsServer     @relation(fields: [vpsId], references: [id], onDelete: Cascade)

  @@map("launch_history")
}
TAREFA 7 — Fluxo do Usuário
Fluxo 1 — Primeiro uso

1. Usuário abre o HEXAGON IDE
2. Tela: Dashboard (vazio)
3. Clica em "VPS" → "Nova VPS"
4. Preenche: nome, IP, porta, usuário, senha
5. Clica "Testar conexão" → app conecta via SSH e confirma
6. Salva a VPS
7. Vai para "Projetos" → "Novo Projeto"
8. Preenche: nome, caminho na VPS, VPS associada
9. Vai para "Contas Claude" → "Nova Conta"
10. Preenche o nome amigável da conta
11. Associa a conta ao projeto
12. Vai para "Lançador"
13. Vê o projeto com botão "IDE"
14. Clica em IDE → ambiente abre
Fluxo 2 — Abrir VS Code Remote SSH

1. Usuário está no Lançador
2. Vê os cards de VPS
3. Clica em "Explorer" ou usa o botão de projeto
4. App monta o URI: vscode-remote://ssh-remote+usuario@host:/caminho/projeto
5. Executa: code --folder-uri <URI>
6. VS Code abre já no diretório remoto correto
7. Usuário autentica o Claude Code dentro do VS Code normalmente
Fluxo 3 — Usar IDE integrado

1. Usuário clica em "IDE" no card da VPS
2. App abre a rota /ide/:vpsId/:vpsName
3. SFTP abre conexão e carrega /root
4. Painel esquerdo: árvore de arquivos
5. Usuário navega pela árvore, clica num arquivo
6. App lê via SFTP e carrega no Monaco
7. Usuário edita com syntax highlighting
8. Ctrl+S → app salva via SFTP na VPS
9. Badge vermelho "PRODUÇÃO" sempre visível
Fluxo 4 — Editar arquivo remoto

1. Usuário clica no arquivo na árvore
2. App verifica extensão:
   - Imagem → carrega como base64, exibe <img>
   - Binário → rejeita com toast de erro
   - Texto → continua
3. App chama sftp:readFile → main lê via SSH
4. Monaco carrega o conteúdo com linguagem detectada
5. Aba aparece com o nome do arquivo
6. Indicador de não salvo: ponto azul na aba
7. Ctrl+S → app chama sftp:writeFile
8. Toast: "arquivo.ts salvo"
9. Aba volta ao estado limpo (sem ponto)
10. Explorer auto-atualiza a pasta pai
Fluxo 5 — Usar terminal SSH

1. Usuário pressiona Ctrl+` ou clica no ícone de terminal
2. App abre painel inferior
3. Clica em "+" para nova aba de terminal
4. App chama terminal:open → main cria sessão SSH shell
5. xterm.js recebe os dados e exibe o prompt da VPS
6. Usuário digita comandos
7. Cada tecla → terminal:input → SSH → resposta → terminal:data → xterm.js
8. Para nova aba: clica "+" → nova sessão SSH independente
9. Troca de aba: histórico preservado (display:none no DOM)
10. Fechar aba: terminal:close → SSH encerrado
Fluxo 6 — Usar Claude no IDE

1. Usuário abre arquivo com bug no editor
2. Clica em botão "Claude" (roxo) na top bar
3. Painel de chat abre à direita
4. App lê automaticamente:
   - Árvore de pastas do projeto
   - Arquivos de docs (CLAUDE.md, README, etc.)
   - Conteúdo do arquivo aberto
5. Usuário digita: "Por que esse código lança TypeError?"
6. App monta o prompt com todo o contexto
7. Escreve em /tmp/hexagon_chat_xxx.txt via SFTP
8. Executa: cd /tmp && claude -p "$(cat arquivo.txt)" --allowedTools '' < /dev/null
9. Claude responde usando o account já logado na VPS
10. Resposta aparece no chat com blocos de código
11. Usuário clica "▶ Aplicar em arquivo.ts"
12. Código substitui o conteúdo do arquivo no Monaco
13. Usuário revisa e pressiona Ctrl+S
TAREFA 8 — Telas do App
Dashboard
Objetivo: Visão geral do sistema.
Componentes: Cards de VPS com status, projetos recentes, ações rápidas.
Ações: Navegar para qualquer seção.
Estado de erro: VPS offline exibida em vermelho.
Carregamento: Skeleton cards enquanto carrega.

Lista de VPS
Objetivo: Gerenciar todos os servidores cadastrados.
Componentes: Cards com IP, usuário, status; botões Editar/Excluir/Testar.
Ações: Criar, editar, excluir, testar conexão.
Estado de erro: "Falha na conexão — verifique IP e credenciais."
Carregamento: Spinner durante teste de conexão.

Cadastro de VPS
Objetivo: Adicionar ou editar uma VPS.
Componentes: Formulário com campos nome/host/porta/usuário/senha; botão Testar Conexão.
Ações: Salvar, cancelar, testar conexão antes de salvar.
Estado de erro: Campos com validação inline; erro de conexão em toast.
Carregamento: Botão desabilitado durante teste.

Cadastro de Projeto
Objetivo: Adicionar ou editar um projeto remoto.
Componentes: Formulário com nome/caminho/VPS/conta Claude; opções para criar pasta ou clonar repo na VPS.
Ações: Salvar, criar pasta remota, clonar repositório.

Cuidado: não sanitizar aqui — é input do terminal, não de formulário

Entrada: { sessionId }

TAREFA 11 — Boas Práticas
Organização de código

packages/
  config/    ← Tipos, schemas Zod, utilitários sem deps
  db/        ← Prisma, migrations, tipos do banco
  core/      ← Serviços de negócio (VpsService, GitService, etc.)

apps/
  desktop/   ← Electron main + preload + IPC handlers
  web/       ← React renderer (nunca importa @cwm/core diretamente)
Regra: O renderer nunca importa código do main. Toda comunicação é via IPC.

Top 5 — O que fazer primeiro e por quê
Monitoramento VPS — É a pergunta mais comum ao trabalhar com servidor: "Como está a CPU? Tem memória sobrando?" Implementar via SSH exec (top, free, df) é relativamente simples e gera enorme valor imediato.

Anthropic API integrada — Substitui claude -p via SSH (lento, 15-30s) por chamada direta à API (rápido, 2-5s, multimodal real). Remove a limitação mais frustrante do chat atual.

Docker Explorer — Grande parte dos projetos modernos usa Docker. Ver containers rodando, iniciar/parar, ver logs — tudo sem sair do IDE.

PM2 / Process Manager — Projetos Node.js usam PM2. Reiniciar um processo sem abrir terminal é muito mais produtivo.

Logs Viewer — Ver o stdout/stderr de processos rodando na VPS em tempo real é essencial para depurar problemas de produção.

O HEXAGON IDE é uma aplicação desktop Electron para Windows que resolve um problema real de desenvolvedores que trabalham com múltiplas VPS e múltiplas contas Claude Code: o conflito de autenticação e a falta de uma interface visual centralizada.

Gerenciador de ambientes — abre o VS Code Remote SSH na VPS e conta corretas
IDE integrado — Monaco Editor + SFTP + Terminal SSH + Git + Chat Claude, tudo rodando diretamente na VPS
